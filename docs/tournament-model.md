# Tournament Rules の形式化メモ（TR 2026-10-09 準拠）

Riftbound の公式 Tournament Rules のうち、形式化の対象にする部分を整理したもの。Core Rules 側は [rules-model.md](rules-model.md)、設計方針は [design.md](design.md) を参照。

> **これは公式ルールの代わりではない。** 規則文は要約であり、厳密な文言は公式 PDF を規則番号で引くこと。

## 0. 出典と版

| 項目 | 内容 |
|---|---|
| 正とする文書 | Riftbound Tournament Rules, **Last Updated October 9, 2026**。公式 Rules Hub（https://playriftbound.com/en-us/rules-hub/ ）からリンクされた PDF |
| 引用形式 | `(TR 402.1)`。Core Rules の `(CR ...)` と区別する |
| Core Rules との関係 | **大会では Tournament Rules が Core Rules に優先する**（TR 104.1）。Core Rules に無い事項を Tournament Rules が補うこともある |

## 1. 形式化の範囲

| 区分 | 対象にするもの | 主な規則 |
|---|---|---|
| フォーマットとデッキ | Constructed / Sealed / Draft の構築規則、カードの合法性、禁止カード | TR 402, 403, 601, 602 |
| マッチ | Bo1 / Bo3、ゲームの結果（引き分けを含む）、ゲームの合間のサイドボード、先手の決め方、Battlefield の再利用 | TR 404, 406, 407 |
| 時間切れ | 時間切れ後の追加ターンと勝敗の決め方 | TR 408, 604 |
| ループ | ループの扱いと、引き分けになる場合 | TR 505 |
| 投了と合意の引き分け | ゲーム・マッチ単位の投了と、合意による引き分け | TR 410 |
| 2v2 | 席順と手番順、先手の決め方 | TR 603 |
| フォーマットによるゲーム中の変更 | Limited で Legend や Chosen Champion を使わない場合の追加ドロー | TR 602.4.a.5.b, 602.4.b.6.b |

**対象外**:
- 大会の運営（参加資格、登録、座席、デッキチェック、記録）。
- ジャッジの手続き、罰則、スポーツマンシップ（TR 300, 411-424, 700-705）。
- コミュニケーションと省略の慣行（TR 500-504）。
- 誘発の忘れ（TR 506）: エンジンは誘発を忘れないので、モデルには現れない。
- タイブレークとスイスのペアリング（TR 202.2, 409）: マッチより上の層なので、必要になったら扱う。

## 2. フォーマットとデッキの合法性

### 2.1 Constructed（TR 402, 403, 601）

| 規則 | 要件 |
|---|---|
| TR 402.1, 601.1.b | **Main Deck はちょうど 40 枚**（Chosen Champion を含む）、Legend 1 枚、Rune 12 枚、**名前の異なる Battlefield ちょうど 3 枚** |
| TR 601.1.c | サイドボードは 10 枚以下で、Main Deck に入れられるカードだけ。同名の枚数制限は、Main Deck とサイドボードの合計にかかる |
| TR 403.4 | ゲームの合間に、サイドボードと Main Deck を 1 対 1 で入れ替えられる。Chosen Champion も替えられる（TR 403.4.a）。Rune、Legend、Battlefield は登録後に変えられない（TR 403.4.b） |
| TR 403.5 | マッチの最初のゲームではサイドボードを使えない |
| TR 403.8 | 次のマッチの最初のゲームの前に、登録した状態に戻す |
| TR 403.10 | 引き分けたゲームの後は、サイドボードを使えない |
| TR 601.2 | 合法なセットのカード（または同名のカード）だけを使える。禁止カードは使えない |
| TR 601.3 | Standard は直近 5〜8 セット（今年と前年のセット）。現在は OGS、OGN、SFD、UNL、VEN、RAD |

**定理の目標**（[roadmap.md](roadmap.md) の I13）: Constructed で合法なデッキからサイドボードを除いたものは、Core Rules のデッキ構築（CR 101-103）でも合法である。Constructed の要件は Core Rules の要件より強い（40 枚以上 → ちょうど 40 枚、など）。

- Battlefield の枚数は、Core Rules ではモードが決める（CR 103.5）。Constructed は 3 枚に固定している。だからこの定理は、Battlefield を 3 枚求めるモード（1v1 Duel など）に限って述べる。
- Core Rules のデッキにサイドボードは無いので、サイドボードを除いた部分について述べる。同名の枚数制限は、大会では Main Deck とサイドボードの合計にかかる（TR 601.1.c）。制限の枚数が Core Rules（CR 103.3.b）と同じであることは、実装のときに原文で確かめる。

### 2.2 Limited（TR 602）

| 規則 | Sealed | Draft |
|---|---|---|
| 資材 | 未開封のブースター 6 パック（TR 602.4.a.1） | 3 パックをドラフト（TR 602.4.b.1）。1 人 39 枚になる |
| Main Deck | **25 枚以上**（TR 602.4.a.2） | **20 枚以上**（TR 602.4.b.3） |
| Domain Identity | 任意の 3 ドメイン、または任意の 1 ドメイン + Legend のドメイン（TR 602.4.a.3） | 同じ（TR 602.4.b.4） |
| Chosen Champion | Identity に含まれる任意の Champion Unit（Champion Tag が一致しなくてよい） | 同じ |
| Signature | Identity に完全に含まれる Signature Spell を使える | 同じ |
| Rune | Identity に合うものを、どこからでも使える（TR 602.4.a.4） | 同じ |
| Legend / Chosen Champion なし | 合法。そのときは各ゲームの最初の Beginning Phase の開始時に 1 枚引く（両方なくても 1 枚）（TR 602.4.a.5） | 同じ（TR 602.4.b.6） |
| 枚数制限 | 同名・Signature の制限なし。Unique も適用しない（TR 602.4.a.6） | 同じ（TR 602.4.b.7） |
| サイドボード | 使わなかったカードすべて。ゲームの合間に Domain Identity・Rune Deck・Legend・Chosen Champion も変えられる（TR 602.4.a.7） | 同じ（TR 602.4.b.8） |
| Battlefield | 配られたもの、または能力の無い「blank」Battlefield を何枚でも（TR 602.3.d）。同じ物理カードは 1 マッチに 1 回まで（TR 602.3.e.4.a） | 同じ |
| 禁止カード | Constructed で禁止でも、その Limited フォーマットで禁止でなければ使える（TR 602.1.b） | 同じ |

- Limited のデッキは Core Rules のデッキ構築を満たさない（40 枚未満がありうる、枚数制限がない）。Constructed と違って、Core Rules との包含の定理は無い。
- 「Legend / Chosen Champion なしで 1 枚引く」は、**フォーマットがゲームの進行を変える例**である。エンジンは、フォーマットからこの種の修正を受け取れるようにする。

## 3. マッチ（TR 404, 406, 407, 408, 410）

- **マッチ**（TR 404）:
  - 一方が所定の勝ち数に達するまでゲームを続ける。多くは Bo3（2 勝）。
  - 引き分けたゲームは勝ち数に数えない（TR 404.3）。
  - 時間切れで所定の勝ち数に達しなければ、勝ち数の多い方が勝ち、同数なら引き分け（TR 404.4-404.5, 408.3）。
  - Core Rules にも 1v1 Match（Bo3: CR 488）がある。「ゲームの結果の列から、マッチの結果と次のゲームの準備を決める」骨格は、両者で共有する。大会に固有の手続き（サイドボード、先手の決め方、時間切れ時の判定）は、その上に載せる。
- **ゲームの開始**（TR 406）:
  - 準備は Core Rules のセットアップ（CR 110）に従う。
  - 引き分けた次のゲームは、同じ Battlefield を使う（TR 406.1.b）。
  - ゲームの敗北の罰則で終わったときは、以後別の Battlefield を使う（TR 406.1.c）。罰則は対象外なので、モデルでは扱わない。
  - Bo1 では、Bo3 に近づけた準備手順を使える（TR 406.1.h）: 各自が 3 枚の Battlefield からランダムに 1 枚を選ぶ → 先手を決める → サイドボード → Chosen Champion を置く → シャッフル。
- **先手の決め方**（TR 407）:
  - 最初のゲームは、ランダムに決めたプレイヤーが、先手か後手かを選ぶ（TR 407.1-407.2）。
  - 2 戦目以降は、前のゲームの敗者が選ぶ。前のゲームが引き分けなら、同じ順を保つ（TR 407.4）。
  - Core Rules（CR 115）は「公平なランダムな方法」としか書いていない。大会ではこの規定が優先する（TR 104.1）。
- **投了と合意の引き分け**（TR 410）:
  - ゲームが終わる前なら、いつでも投了できる。全員が合意すれば引き分けにできる（TR 410.1）。マッチでも同じ（TR 410.2）。
- **2v2**（TR 603.7）:
  - 手番順は「先手チームの A → 後手チームの A → 先手チームの B → 後手チームの B」。
  - 先手を選ぶチームはランダムに決める。2 戦目以降は、前のゲームで負けたチームが選ぶ。

## 4. 時間切れ（TR 408, 604）

- **スイスのラウンド**（TR 408.2）:
  1. 時間切れの時点の Turn Player は、そのターンを最後まで行う。
  2. その後、追加で 3 ターン行い、マッチを終える。
  3. ゲームが終わっていなければ、**2 点以上リードしているプレイヤーがそのゲームの勝者**。そうでなければ、そのゲームは引き分け。
  - ゲームの合間に時間切れになったら、新しいゲームは始めない（TR 408.2.d）。
- **シングルエリミネーションで時間を区切る場合**（TR 408.4）:
  - 追加の 3 ターン後に点数の多い方がゲームに勝つ。
  - 点数もマッチの勝ち数も同じなら、次に点を取った方がマッチに勝つ（サドンデス）。Final Point の制限は残る（TR 408.4.c.3）。
  - 勝ち数が同じで新しいゲームを始める場合は、始めた直後に時間切れになったものとして扱い、追加ターンは 5 にする（TR 408.4.d）。
- 推奨の時間は、スイスで 60 分（TR 604.1）。

**モデル化**: 時間切れは、エンジンの外から来るイベント（行為者を「時計」とする `Action`）として受け取る。受け取った後は、残りターン数のカウンタと、ゲームの結果の判定（点差）をエンジンが持つ。

## 5. ループ（TR 505）

- 繰り返せる手順は、ループとして省略できる。各周回は、同じカードに対する同じ無条件の行動でなければならない（TR 505.2）。確率や条件分岐を含むものは、ループとして省略できない（TR 505.2.a, 505.9）。
- ループを維持するのに必要なプレイヤーの人数で場合分けする（TR 505.3）。
  - 維持するプレイヤーは、手番順に周回数を選ぶ（TR 505.4）。
  - 他のプレイヤーは、その数に同意するか、ループを断つ周回数を選ぶ（TR 505.5）。
  - **誰もループを断たず、維持するプレイヤーもいなければ、ゲームは引き分けになる**（TR 505.6）。
  - それ以外は、最も小さい周回数まで進み、そのプレイヤーが Priority を得るか、ループを断つ（TR 505.7）。
- 状態を変えないループで時間を稼ぐことは禁止（TR 505.13）。これは行為の規範なので、モデルでは扱わない。

**モデル化**:

- **引き分けの宣言は、ジャッジを行為者とする `Action` で受ける。**
  - TR 505.6 の条件（誰もループを断たず、維持するプレイヤーもいない）は、プレイヤーの宣言とジャッジの判断で決まる。時間切れと同じく、エンジンの外から来るイベントとして扱う。
  - エンジンは、この `Action` を受けたらゲームを引き分けで終える。大会の設定でだけ合法とする。
  - エンジンは、ループを自動では検出しない。
- **エンジンの中で「状態が繰り返したら引き分け」としない理由**:
  - 状態は完全には繰り返さない。Non-Board ゾーンを通るたびに新しい ObjId を払い出し、Chain 上の能力もオブジェクトで、効果の適用ごとに timestamp が進む（[design.md §5.1](design.md#51-識別子)）。誘発を含むループでは、払い出しのカウンタが毎周増える。
  - ループは、自動処理の中に収まらない。Chain に載った誘発能力は Execute と Pass の段を通り（CR 338-339）、各プレイヤーがパスを答える。コアは選択肢が 1 つでも決定要求を出すので（[design.md §6.3](design.md#63-できること全ての担保)）、強制的な誘発のループは `step` の呼び出しをまたぐ。
- **強制的なループの検出器**（自動対戦のため。[roadmap.md](roadmap.md) M9）:
  - エンジンの外に、別の関数として置く。入力は、決定点ごとの状態と、そこでの答えの履歴である。
  - 次の 2 つがそろったときに、ループを報告する。
    1. 履歴の中の 2 つの決定点の状態が同値である。同値とは、ObjId の付け替えと、順序を保つ timestamp の付け替えを除いて等しいこと。隠れ情報の非干渉（[design.md §6.5](design.md#65-隠れ情報)）で使うものと同じ定義である。
    2. その間の答えがすべて強制だった。強制とは、投了と引き分けの提案を除いて、合法手が 1 つしか無かったこと。偶然の決定をはさむ区間は対象にしない（TR 505.2.a）。
  - このとき、どのプレイヤーにもループを断つ手段が無く、維持する選択もしていない。以後も同じことが繰り返されるので、TR 505.6 の条件を満たす。Driver は、ジャッジの `Action` を送ってゲームを引き分けにする。
  - 検出器の健全性（報告したら、強制的な答えだけで同値な状態に戻り続ける）は、定理として示す（roadmap.md の I19）。
  - `detectExactForcedLoop` は、識別子を含めて状態が一致する場合を検査する。履歴の各回答を再実行して強制手であることを確かめ、開始状態に戻れば何周でも同じ回答を繰り返せる。自動対戦の Driver は強制手が続いている間の履歴を保持し、この検査でループを確認した場合にジャッジの引き分けを送る。識別子の付け替えを含む同値性は未実装。
  - この検出器は、TR 505.6 の一部しか覆わない。断つ手段はあるが誰も断たないループは、プレイヤーの宣言が要るので、検出の対象外である。カウンタが増え続けるなど、状態が同値に戻らないループも検出できない。
- **プレイヤーが維持するループ**は、プレイヤーが毎周決定を出すだけなので、エンジンの側に特別な処理は要らない。周回数をまとめて指定する省略（TR 505.4-505.7）は、Driver の機能として後から足せる。
- **fuel** は、決定を挟まない自動処理が止まらない場合の安全弁として残す。尽きたら `fuelExhausted` のエラーを返す。
- Core Rules だけで遊ぶ場合（大会のルールを使わない設定）は、ループの規定が無い。ジャッジの `Action` は合法でなく、止まらない自動処理は fuel 切れのエラーになる。

## 6. 設計への影響（design.md に反映済み）

| 論点 | 決定 |
|---|---|
| ゲームの結果 | 「勝者あり」に加えて「引き分け」を持つ（ループ、時間切れ、合意） |
| 規則の選択 | 対局の規則（`GameConfig`）に、「Core Rules のみ」か「大会」かと、フォーマット（Constructed / Sealed / Draft）を持つ。ゲームモード（Duel など）とは別の項目。初期状態に入れ、対局中は変えない |
| 設定の妥当性 | TR が手続きを定めていない、モードとフォーマットの組を除く述語（`GameConfig.Valid`）を置く |
| 優先関係 | 大会の設定では、Tournament Rules の規定を Core Rules より優先する（TR 104.1） |
| 時間切れ | 「時計」を行為者とする `Action` で受け取る |
| ループ | 引き分けの宣言は、「ジャッジ」を行為者とする `Action` で受け取る。エンジンは自動では検出しない。強制的なループの検出器を、エンジンの外に置く（§5） |
| マッチ | ゲームの上の層として `Match` を持つ。ゲームの結果の列から、マッチの結果とサイドボードの可否、次のゲームの先手を決める。骨格は Core Rules の 1v1 Match（CR 488）と共有する |
| デッキの合法性 | `DeckValid`（Core Rules）、`ConstructedDeckValid`、`SealedDeckValid`、`DraftDeckValid` を別の述語にする |

## 7. 曖昧な点と要確認事項

1. **TR 408.4.c.3 の参照先**: 「See CR 469.1.a. for Final Point details」とあるが、CR 2026-10-09 版の Final Point は 473.1 にある。番号が古い。
2. **Bo1 の準備手順**（TR 406.1.h）は、ヘッドジャッジが選べる任意の手順である。モデルでは、通常の手順と選べる設定にする。
3. **追加ターンの数え方**: 時間切れ後の「追加 3 ターン」に、カードの効果による追加ターン（CR 734）を数えるかは明記されていない。TR 206.1 は、ラウンドサイクルが追加ターンの影響を受けないとしている。実装時に確かめる。（実装: 追加のターンも `turn` に数え、時間切れの判定に含める。時計の不変条件を壊さないため。ターン順の計算だけは、`turnShift` で、追加のターンを数えない。）
4. **2v2 での時間切れ**: 点差 2 点の判定は、チームの共有点（CR 491.8.d）で行うと読める。
5. **TR 505.6 を判断する主体**: 「誰もループを断たない」「維持するプレイヤーがいない」は、プレイヤーの宣言とジャッジの判断で決まる。モデルでは、ジャッジを行為者とする `Action` として外から受け取る（§5）。
6. **有効なモードとフォーマットの組**: どの組に TR が手続きを定めているかは、TR 600 番台で確かめる（`GameConfig.Valid` の中身になる）。
7. **Core Rules の 1v1 Match（CR 488）と TR のマッチ（TR 404）の関係**: 先手の決め方や Battlefield の扱いが両者でどう違うかは、マッチを実装するときに原文で確かめる。
8. **Sealed と Draft の Domain Identity**: 任意の異なる 3 ドメイン、または Legend のドメインと任意の 1 ドメインの和集合を宣言できる。Legend がすでに持つドメインを選んだ場合、宣言にはそのドメインを 1 回だけ含める。 [公式 Tournament Rules 602.4.a.3・602.4.b.4](https://cmsassets.rgpub.io/sanity/files/dsfx7636/news_live/861752822d217edf37d9febaeaf77a7d924c1bb6.pdf#page=27)
9. **Limited の Main Deck の枚数の数え方**: Chosen Champion を含めて数えた（Constructed と同じ）。原文で確かめる。Limited の Battlefield の枚数と「blank」Battlefield（TR 602.3.d）、Rune Deck の枚数（CR 103.4 の 12 枚を仮定した）も未確認。
